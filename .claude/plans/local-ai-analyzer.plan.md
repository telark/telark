## Approach

Refactor the Python analyzer service in place into the 'local analyzer' (Python kept, U-7: FastAPI + uvicorn, pydantic v2, redis.asyncio, httpx, loguru; the provider stack, instructor and anthropic go), keeping the directory, module layout, chart slot, image repo, Dockerfile base, service id and nginx location (U-4). Order is contract-first: CRD yaml (S1) before the Go GlobalConfig field (S2), shared data/rest types (S2, S3) before any consumer. The exporter loses the provider-key Secret path entirely (S4); a Helm pre-upgrade hook Job deletes the kept Secret (S15, U-5). Discovery loses the 5-minute all-apps tick, the analyzer HTTP client, its circuit-breaker slot and the connectivity gate (S5); it keeps the windowed read route on the same Redis key `analyzer:{ns}:{name}` but now filters `?apps=` by GlobalConfig.excludedNamespaces (S6, U-3) and emits a best-effort XADD to `insights:jobs` when a publish authored an incident or recovery change-log entry (S7). The analyzer (S8-S14) is one asyncio worker task consuming that stream (group `analyzer`, replicas=1 via HPA exclusion), running a native Ollama `/api/chat` tool loop over four read-only, typed, capped tools, then an EMIT call with the identical tools array plus a JSON schema (maxItems 3), writing ONE atomic document per run with a code-owned insight lifecycle (dedup id = sha256(ns|name|subject)[:16], model omission never resolves, recovery jobs resolve in code with no model call). It serves manual Analyze, runtime status/validate/pull and a fetch-streamed SSE endpoint (FastAPI StreamingResponse) fanned out in-process (no per-connection XREAD). Helm owns Ollama (default OFF, PVC keep, empty pull list, NetworkPolicy, conservative securityContext, 5Gi/6Gi CPU profile for qwen3:4b, U-1/U-6). The UI replaces polling with one initial GET + SSE + version-driven refetch and gets a Settings section with runtime status, model select (tools-capability validated, license label), Install model progress, enabled and autoAnalyze toggles (autoAnalyze seeds false, U-2). Zero impact on core Telark when the analyzer is off, absent or failing: discovery only XADDs (errors logged), the read route still serves the last document, nothing gains workload-write RBAC.

## Lifecycle / state machine

INSIGHT DOCUMENT (Redis string `analyzer:{ns}:{name}`, TTL 7d refreshed on every write, one SET per run): AppInsights{insights[], lastRun{status queued|running|done|failed, trigger manual|incident|recovery, runId, queuedAt, startedAt, finishedAt, error, model, steps, toolCalls, truncated}, version int monotonic}. Insight{id, kind enum [crashloop,oom,image_pull,probe_failure,scheduling,rollout_stuck,config_change_regression,resource_pressure,other], subject 'deployment/api' (kind lowercased + name that must match a get_app_overview workload), title<=120, summary<=400, confidence low|medium|high, severity info|warning|critical, status open|updated|resolved, evidence[{type change|snapshot|event|workload, ref}], firstSeenAt, lastSeenAt, resolvedAt, runs}. id = sha256(ns|name|subject)[:16] from analyzer-validated fields; kind is an attribute, never keyed.

RUN STATES: manual analyze -> lastRun=queued{runId, queuedAt} written by the handler (version++; skipped when lastRun.runId already equals that id, i.e. the worker got there first). Every ACK-and-drop of a job (stale >30 min, inflight held, autoAnalyze off, auto cooldown) writes lastRun=failed (job_expired | run_in_progress | job_dropped) only while lastRun still shows that runId queued or running (running = a crash-reclaimed message), then publishes analysis.failed; an unexpected exception inside a run writes failed internal_error and publishes analysis.failed; a queued lastRun older than 30 min (nothing consumes while the analyzer is disabled) is rendered failed job_expired by the UI. Every document write is one InsightStore.update (get, change, put under one asyncio.Lock; one analyzer replica on one event loop). job consumed -> inflight SET NX EX 540 -> lastRun=running written (version++) -> loop -> EMIT -> merge -> lastRun=done written (version++). Failed run: only lastRun written (insights untouched). Truncated run: insights written with confidence clamped low, resolves nothing. Recovery job: code only, no model call: every open/updated insight -> resolved, lastRun=done trigger=recovery.

MERGE (per emitted insight, after Go validation: subject matches an overview workload, refs subset of refs returned by tools this run, unknown refs dropped, 0 refs -> dropped unless kind=other -> confidence low, same subject twice -> keep higher severity): existing open|updated -> status updated, summary/title/evidence/kind/severity replaced, runs++, lastSeenAt=now; existing resolved -> reopened as open, runs++, resolvedAt cleared, firstSeenAt kept; new -> open, firstSeenAt=lastSeenAt=now, runs=1. Not re-emitted -> unchanged. confidence clamped low when refs<2 or run truncated.

RESOLVE (code only): (1) recovery job resolves all open/updated; (2) after an untruncated run (truncated = forced EMIT or any tool timeout, k8s_error or k8s_unavailable), for each open|updated insight that Merge did NOT create, update or reopen this run and whose subject workload was fetched by get_workload_status this run: resolved when cached status shows ready==desired, no pod waitingReason, and the cached get_recent_events result holds no Warning for that object newer than lastSeenAt. resolved entries pruned on write once resolvedAt is older than 7d. stale (lastSeenAt>24h and not resolved) is UI-derived only.

TRIGGERS: manual POST analyze (Write applications): 404 app missing or primary namespace excluded; 409 analyzer_disabled; 503 runtime_<state> when runtime != ready; 202 {runId, status:running} when inflight; 429 cooldown_active when analyzer:cooldown:manual:{ns}:{name} SET NX EX 60 fails; 429 queue_full when XLEN insights:jobs >= 100 (the worker XDELs every message right after its XACK, so XLEN = undelivered + pending backlog); else XADD, write lastRun=queued (RUN STATES) and 202 {runId=<stream id>, status:queued}. incident/recovery XADD from discovery: analyzer drops when GlobalConfig.ai.autoAnalyze=false (checked by the analyzer); incident additionally gated by analyzer:cooldown:auto:{ns}:{name} SET NX EX 600; recovery has no cooldown. Jobs whose stream id timestamp is older than 30 min at consume -> ACK+drop. App 404 at run start -> DEL document, ACK.

RUNTIME STATES: absent (OLLAMA_HOST DNS 'no such host'), unreachable (any other /api/tags error), model_missing (/api/show 404; Check never pulls: a pull starts only when the worker consumes a job while enabled with autoPull on and no pull running, or from POST runtime/pull), pulling, unsupported (/api/show capabilities lacks 'tools'), ready. Re-checked before every run and every ANALYZER_CONFIG_POLL_SEC; each change pushes runtime.changed.

SSE: GET insights/events?apps=ns/name,... (Read applications); apps in excludedNamespaces dropped from the subscription; events {analysis.queued, analysis.started, analysis.failed, analysis.finished, insight.created, insight.updated, insight.resolved} carry {app, version,...} and go only to subscriptions holding that app; {runtime.changed, runtime.pull} go to every subscriber; `resync` is sent when a per-connection buffer overflows; `: ping` every 15s. UI: initial GET, then GET whenever an event's version > local version, GET on reconnect and resync. No optimistic patches and no client-side queued flag: Queued is read from the fetched lastRun (status queued, queuedAt within 30 min); analyze() GETs after its 202.

## Decisions

- **In-place refactor or new service, and in which language?** — Refactor services/analyzer in place and keep it Python (U-7): FastAPI + uvicorn, pydantic v2, redis.asyncio, httpx, loguru — all already in requirements.txt; instructor and anthropic leave with the providers. Keep the name, chart key, image repo, Dockerfile base, SA, nginx /api/analyzer/ location and base.Analyzer service id (U-4), the module layout, authz.py and the pytest suites. *Why:* User decision U-7 (2026-09-23 20:00, final); no host/registry/nginx churn and no new CI, Makefile or go.work wiring; rename is cosmetic and deferred (design D1).
- **Where do insights live and who serves reads?** — Same Redis key `analyzer:{ns}:{name}`, one JSON document, one SET per run, TTL 7d. Discovery keeps the read route (now filtering by excludedNamespaces); the analyzer serves only analyze/events/runtime. *Why:* Zero impact when the analyzer is off/absent (last document still readable); O(1) read; no sweep/lock/index (design D2, U-3).
- **Trigger transport** — Redis stream `insights:jobs` (XADD MAXLEN~1000 from discovery publish path, consumer group `analyzer`, one worker), manual POST on the analyzer. No periodic tick. *Why:* Recovery signal resolves insights; removes HTTP client, breaker slot, connectivity gate and the all-apps tick. NATS JetStream here is WorkQueuePolicy with one durable consumer per topic; a list has no ACK/claim (design D3, D11).
- **Tool set** — Exactly four typed tools: get_app_overview, get_change_history (from the fetched CR, 0 k8s calls), get_workload_status, get_recent_events (per-namespace Warning list, Limit 200, the analyzer filters involvedObject by exact generated-name regexes). No metrics, no kubectl, no raw passthrough. *Why:* No unverified exporter route, no extra RBAC beyond get/list on pods, events, deployments, statefulsets, daemonsets, replicasets (design D4, R8, R14).
- **Outbound calls without new dependencies** — Ollama (/api/tags, /api/show, /api/chat, /api/pull) and the Kubernetes API (GET only, the pod's service-account token + CA) are called with httpx.AsyncClient; the exporter with httpx + X-Service-Token, as provider_config.py did. *Why:* httpx is already in requirements.txt; an ollama SDK, the kubernetes client or instructor would add dependencies for four endpoints and three GET paths, and U-7 rules out an agent framework.
- **LLM protocol** — Native /api/chat, stream:false, think:false, truncate:false, shift:false, options{num_ctx 8192, temperature 0.2, num_predict 400 (loop) / 1024 (emit)}, keep_alive 30m; <=2 tool calls per step; EMIT keeps the identical tools array and adds format=<schema {insights: array maxItems 3}>; 2 consecutive invalid tool calls abort; per-request fit check (bytes/3.5 vs last counters, never cumulative); wall 480s with a 300s EMIT reserve. *Why:* /v1 has no num_ctx/tool_choice; dropping tools at EMIT discards the KV prefix; Ollama's silent truncate/shift would drop the user message without signal (design D6, D7, R2, R3, R7, R13).
- **Default model and validation** — GlobalConfig.ai.model seeds `qwen3:4b` (Apache-2.0, tools capable); Settings lets Owners change it; POST runtime/validate requires /api/show capabilities to contain `tools` (422 model_lacks_tools) and returns a licence label (qwen2.5:3b = research/non-commercial warning). No live smoke chat. *Why:* U-1; qwen2.5:3b is Qwen RESEARCH; a synchronous smoke would exceed nginx proxy_read_timeout 30s and the UI 30s timeout (design D8, R1, R9).
- **Ollama ownership** — Helm renders the subchart (app.ollama.enabled default false, app.ollama.autoPull true), Settings only toggles usage and shows runtime state plus the exact `--set app.ollama.enabled=true` hint when absent. No Telark reconciler, no second chart. *Why:* Nothing in Telark gains workload-write RBAC; GitOps-native (design D9).
- **Provider key removal and the kept Secret** — Exporter divert/inject/AIKeyStore/Role rule/env deleted; chart Secret template deleted; a hook-annotated pre-upgrade Job (curl DELETE with a hook-scoped SA/Role limited by resourceNames, 404 = success) removes `<app.name>-ai-provider-key`. *Why:* U-5: no documented kubectl step; resource-policy keep would otherwise strand the Secret (design D13).
- **SSE transport and auth** — fetch()-streamed SSE (ReadableStream) with the existing X-Session-Token header, in-process broadcaster (per-connection asyncio.Queue, maxsize 32, overflow -> drained + resync) served by a FastAPI StreamingResponse, events carry version, UI GETs on version change/reconnect. Token never in the URL. nginx: no edit (the analyzer upstream keepalive_timeout 3s stays below uvicorn's 5s idle close, nginx.conf:36-37). *Why:* EventSource cannot send headers; per-connection XREAD would exhaust REDIS_POOL_SIZE=10; X-Accel-Buffering: no is honoured by the existing nginx config (design D12, R10).
- **autoAnalyze default** — false on fresh installs; incident/recovery jobs are dropped by the analyzer until an admin enables it. *Why:* U-2.
- **Notifications** — None in V1. dashboard-ui notifications typeRegistry.ts is NOT touched. *Why:* Design Consumers row keeps it (V1 emits no notification); the task text's 'notification registry' mention is superseded by the design, which is the source of truth.
- **UI naming** — 'Local analyzer', 'analyzer', 'model', 'model runtime'. The only place the string `ollama` appears in the UI is inside the verbatim Helm hint code snippet (`--set app.ollama.enabled=true`) shown when the runtime is absent. *Why:* Memory rule: no vendor names in UI prose; the values key is the operator's install command and cannot be paraphrased (design D14).
- **LastRun carries runId and queuedAt** — AppInsights.lastRun gains `runId` (the stream message id, or the analyze response id) and `queuedAt` (omitempty; set by the analyze handler while a manual job waits). *Why:* The UI correlates analysis.* events with the document and derives Queued from server truth, expiring it after 30 min like the worker's stale drop (R2-1); the design's LastRun omitted both — two string fields, no other shape change.
- **Which namespace keys the document for a multi-namespace app?** — app.Namespaces.Items[0].Name (primary), exactly what discovery's old primaryNamespace() and the UI's Content.tsx primaryNamespace already use. *Why:* Keeps the key stable across the rewrite; the UI passes the same value.
- **Autoclean rail** — railNoAnalyzerLock -> railNoAnalyzerInflight: SCAN `analyzer:inflight:*:<appName>` (count 10), pass when no key. *Why:* The old lock:enrich: key was never written; the rail only has the app name (same shape as railNoGenerationLock).

## Phases

**Goal:** Persisted shape, stream message fields and endpoint constants exist before any consumer; CRD yaml lands before the Go field so nothing is pruned.

**Steps:** S1, S2, S3

**Acceptance criteria:**

- internal/rest: `go test ./...` and `golangci-lint run` zero issues; `grep -rn "clients/insights\|endpoints/provider" services internal` returns nothing once S5 has deleted discovery's clients/analyzer.go (the last consumer after S3).

**Goal:** No code path reads, writes or injects an AI provider key; the ai field stays Owner + controlainsights.

**Steps:** S4

**Acceptance criteria:**
- services/exporter: `go test ./...` and `golangci-lint run` zero issues; `grep -rn 'AIKeyStore\|injectAIKey\|divertAIKey\|clearAIKey\|MayControlAIInsights\|AIKeySecret\|FieldAPIKey\|ErrAIKey' services/exporter` returns nothing (symbol grep: internal/tests/logs/logs_test.go:23 keeps its `apikey` leak pattern unchanged); TestGuardGlobalConfigPatchLevelPerField and ...HonoursDenyRules unchanged and green.

### P2 — Phase 2 — Discovery: tick removed, read route filtered, triggers emitted

**Goal:** Discovery neither calls nor depends on the analyzer; it filters insight reads by visible namespaces and XADDs incident/recovery jobs best-effort.

**Steps:** S5, S6, S7
