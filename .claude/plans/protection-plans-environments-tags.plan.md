**Invariants:**
- CRD yaml changes before any Go struct gains a field (strict structural schema prunes silently: 200 with data gone). S1 precedes S3 and S4.
- Environment/tags are metadata only. policies.Render, RenderMeta and the exporter plan handler are untouched.
- No validation of the new fields goes into the exporter's plan create/patch path: any exporter 4xx reaches the UI as 503 (discovery handlers/plans/protection/errors.go:27-28). Size validation (length/count, mirroring the CRD) lives in discovery validation.Fields.
- Absent never means clear on update: PrepareProtectionPlanRequest carries EnvironmentID *string and TagIDs []string (encoding/json gives nil for a missing key, a non-nil empty slice for []); PatchProtectionPlanRequest carries *string / *[]string so an empty value survives MapToJSONPayload; DuplicateProtectionPlanRequest carries EnvironmentID *string and TagIDs []string (it is only ever json-decoded, never mapped) so a duplicate can distinguish 'copy the source' (nil) from 'clear' ([]). nil = keep/copy, "" / [] = clear.

## Approach

Environments and Tags are two new scope values on the existing Category mechanism ('plan-environments', 'plan-tags'), not new entities: the category CRD scope is a free string (category.yaml:57-61), seeding is scope-blind (exporter startup/seed.go:49-71 + data builtin.go:50-58), the six category routes are Authenticated and scope-parameterised (exporter authz/requirements.go:94-101), and the UI clients/store are keyed by scope. The single backend blocker is GuardCategoryScope (exporter authz/guard.go:153-195), which uses the taxonomy scope as the authz scope and 403s unknown scopes before Allows; it is fixed by a two-entry governing-scope map (plan-environments / plan-tags -> protection-plans) applied with cmp.Or to Requirement.Scope and RuleKey, and the plan scopes reuse the existing protection-plans actions (createprotectionplan at Contributor, editprotectionplan at Owner) so no new deny vocabulary is hand-synced across four files. Plans gain two optional fields, environmentID (string) and tagIDs ([]string), added CRD-first (not in spec.required, bounded by maxLength 19 / maxItems 20 only), then the data struct (omitempty), then rest DTOs (Create plain; Prepare and Duplicate: *string + []string, both only ever json-decoded, nil = keep / copy; Patch: *string + *[]string so an explicit empty value survives MapToJSONPayload's omitempty skip at rest mappers/payload.go:40-42,88-91,112-116), then the four discovery enumeration sites (buildPlan, toCreateRequest, BuildPatch, duplicate.BuildRequest) plus length/count/duplicate validation in validation.Fields. The renderer is untouched. UI: an 'Organize' dropdown (Environments / Tags) in the plans toolbar inserted BEFORE the canCreate gate, the zero-plans early return in MainPage removed (ProtectionPlansListPage renders the empty page in its data region directly after the error branch, before the spinner, so today's behaviour is kept with no new state), one PlanTaxonomyPage reusing PageLayout + the shared category columns/panels with scope-driven wording from a complete-tree label factory, one shared PlanTaxonomyFields (environment single Select + tags multi Select) used by the create/edit form AND the duplicate panel (which resets its form on open and sends the two keys only when touched), chips on the card, rows on details, two client-side filters. The shared useCategories hook fetches a scope once (key presence in categoriesByScope, inlined selector); a rejected fetch leaves the key absent and is retried on the next mount. Only the two page surfaces (list page, details Content) fetch; the form hook, the card and the duplicate panel read the store. Dangling ids (deleted entry) are tolerated with neutral rendering (card omits, details shows the em dash, form/filter Selects show the raw value) — no 'Removed' placeholders. A read-only V0 step snapshots the branch and `git diff HEAD` of every tree so V3 can isolate the feature diff from the pre-existing dirty state. Release order (user-owned): data tag -> rest tag -> telark pins + CRD chart -> exporter -> discovery -> dashboard-ui.
